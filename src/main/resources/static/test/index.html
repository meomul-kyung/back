머물;경 백엔드 API 테스트 콘솔

사용 순서
1. 백엔드를 localhost:8080에 띄운다 (docker compose up -d 후 앱 실행)
2. 카카오 로그인 클릭 → 로그인하면 프론트 콜백 주소로 ?accessToken=...이 붙어 리다이렉트된다. 그 주소창에서 토큰만 복사해 위에 붙여넣는다. (토큰 유효 30분)
3. 아래 API들을 위에서부터 실행해본다. 일정을 먼저 만들어야 마이페이지에 볼 게 생긴다.

이 페이지는 스프링이 정적 리소스로 서빙한다. 백엔드와 같은 오리진(localhost:8080)이라 CORS가 아예 걸리지 않으므로 별도 서버를 띄울 필요가 없다. 주소는 http://localhost:8080/test/ 이다.

0. 공개 API (인증 불필요)

GET/api/travel-options
여행 조건 선택지 조회. 취향 태그·동행 유형·숙박 범위를 내려준다. 추천 화면 진입 시 호출.
—

1. 회원

GET/api/users/me🔒
현재 로그인한 회원 정보와 온보딩(닉네임 등록) 완료 여부. onboardingCompleted가 false면 닉네임 등록 화면으로 보낸다.
—
GET/api/users/nickname-availability🔒
닉네임 중복 확인. 본인이 이미 쓰는 닉네임은 사용 가능으로 처리된다.
—
PATCH/api/users/me/onboarding🔒
최초 로그인 사용자의 닉네임 등록. 성공하면 onboardingCompleted가 true가 된다.
—
PATCH/api/users/me🔒
개인정보(이름·닉네임) 수정.
—

2. 지역 추천

POST/api/regions/recommendations🔒
취향 최대 3개·동행 유형·숙박일을 기준으로 상위 3개 지역을 추천한다. 태그 가중치 매칭이라 외부 API를 쓰지 않는다.
—

3. 체류형 일정 — TourAPI 필요

POST/api/itineraries🔒
선택 지역·시작일·숙박일 기준으로 일정을 자동 생성한다. TourAPI를 실시간 호출하므로 인증키가 없거나 네트워크가 막히면 500이 난다. 성공하면 아래 입력칸들에 itineraryId가 자동으로 채워진다. 
—
GET/api/itineraries/{id}🔒
일정 상세. 일자별 날씨와 장소(관광지·음식점·체험·축제)를 함께 준다.
—
GET/api/itineraries/{id}/weather🔒
일자별 날씨. 기상청 API허브 단기예보 기준 오늘~+3일만 값이 오고, 그 밖의 날짜는 available: false다. 인증키 미승인·호출 실패도 available=false로 나간다(에러 아님). 
—
POST/api/itineraries/{id}/regenerate🔒
같은 조건으로 방문 장소를 다시 추천한다. 완료된 일정은 409.
—
POST/api/itineraries/{id}/items/{itemId}/replace🔒
개별 장소 교체. 축제 항목은 개최 기간이 고정이라 교체 대상에서 제외된다(409).
—
PUTDELETE /api/itineraries/{id}/bookmark🔒
일정 저장 / 저장 해제. 중복 요청에도 동일 결과다. 저장한 일정은 마이페이지 저장 목록에 뜬다.
—
POST/api/itineraries/{id}/completion🔒
여행 완료 등록. TourAPI를 호출하지 않으므로 일정 행만 있으면 동작한다. 스탬프를 지급하고 지역 기여도를 산출해 저장한다. 응답의 contribution.calculationStatus가 CALCULATED여야 정상이다. 같은 일정을 두 번 완료하면 409.
산입 일수 = 24시간마다 1일 + 나머지 3시간 이상이면 +1일 · 예상 소비 = 66,000원 × 인원 × 산입일수 
—

4. 마이페이지

GET/api/users/me/completed-trips🔒
완료 여행 목록. regionId를 주면 해당 지역만. 데이터가 없는 지역은 에러가 아니라 빈 배열이다.
—
GET/api/users/me/completed-trips/{completedTripId}🔒
완료 여행·기여도 상세. 기여도 스냅샷과 해당 지역 스탬프를 함께 준다. 지출은 두 가지 — reportedSpending(사용자 입력한 실제 지출), estimatedSpending(국민여행조사 단가 기반 추정). 남의 기록은 403, 없는 기록은 404. 
—
GET/api/users/me/stamps🔒
스탬프 현황. 미수집 지역까지 15개 전체를 collected:false로 함께 내려주므로 프론트는 배지 그리드를 그대로 렌더링하면 된다. 
—
GET/api/users/me/contribution-summary🔒
기여도 요약. 전체 누계와 지역별 누계를 함께 준다. 제안서의 지표 4종이 각각 visitedRegionCount / totalStayHours / totalEstimatedSpending / totalPopulationContributionDays에 대응한다. 합계가 위 완료 여행 목록의 값을 더한 것과 일치해야 한다. 
—
GET/api/users/me/bookmarked-itineraries🔒
저장(책갈피)한 일정 목록. 최근 저장순.
—

5. 권한·에러 확인

토큰 없이 호출하면 401이어야 한다. 302 리다이렉트가 오면 SecurityConfig 문제다. 없는 기록은 404 COMPLETED_TRIP_NOT_FOUND, 남의 기록은 403 COMPLETED_TRIP_ACCESS_DENIED.
